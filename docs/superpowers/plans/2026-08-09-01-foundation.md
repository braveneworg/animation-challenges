# Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up a running, type-checked, linted, tested React 19 application shell with a validated challenge catalog registry, so every later plan has a verified place to add code.

**Architecture:** A single Vite SPA. Challenge content lives as typed TypeScript modules collected by `import.meta.glob` into a registry; a pure `buildRegistry` function does the collection so it can be unit-tested against fixtures without touching real content. A static integrity suite asserts catalog invariants that do not need the runner. Tests split into a node `unit` project and a Playwright-backed `browser` project, because jsdom cannot resolve animated computed styles (spec §8.1).

**Tech Stack:** React 19.2.8 · TypeScript 7.0.2 · Vite 8.2.1 · Vitest 4.1.10 · TanStack Router 1.170.25 · TanStack Query 5.101.4 · Tailwind CSS 4.3.3 · shadcn/ui · Zod 4.4.3 · oxlint 1.77.0 · Prettier 3.9.6 · pnpm 11.21.0 · Node 24.18.0

**Spec:** `docs/superpowers/specs/2026-08-09-animation-challenges-design.md`

## Global Constraints

- **No `any` type.** Enforced by `typescript/no-explicit-any` in oxlint.
- **No lint disable comments.** Neither `oxlint-disable` nor `eslint-disable`. Enforced by `pnpm lint:no-disable`, which fails the build on either spelling.
- **TypeScript 7.0.2 exactly.** Do not install `typescript-eslint`; it hard-refuses TS 7.0 (spec §9.1).
- **Optional interface properties are declared `prop?: T | undefined`.** `exactOptionalPropertyTypes` is on, and Zod's inferred output types are otherwise unassignable.
- **Prettier:** `printWidth: 120`, single quotes, `trailingComma: 'all'`, semicolons, `arrowParens: 'always'`.
- **Commits:** Conventional Commits, atomic, on branch `feat/animation-challenges-platform`. Never commit to `main`. No AI attribution or `Co-authored-by` lines.
- **Package manager:** pnpm 11.21.0 via corepack. Never `npm install`.
- **The catalog manifest is 123 challenges across 22 categories**, per spec §4.1. Category `plannedCount` values must sum to 123.
- **TDD:** write the failing test, run it, watch it fail, then implement.

**8 · Task 5 Step 1 — `lucide-react@1.31.0` trips the supply-chain gate.** It was published the day this plan was written. pnpm rejects it with `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION` and auto-creates a `pnpm-workspace.yaml` carrying a `minimumReleaseAgeExclude`, silently disabling the check. Prefer the previous minor.**

**9 · Task 5 Step 6 — the shadcn CLI cannot resolve `@/*`.** This is a solution-style root `tsconfig.json` with only `references`, so the CLI writes components into a literal `./@/` directory. Add a `compilerOptions.paths` block mapping `"@/*": ["./src/*"]` to the root config; it is inert for `tsc` because that config has `"files": []`.

**10 · Task 8 Step 5 — the schema admits malformed ids.** The two `id` refines check the prefix and the slash count but nothing about the slug, so `'css-transitions/'`, `'css-transitions/Hover Lift!!'`, and `'css-transitions/hover-lift   '` all validate. Since the id is the progress key and drives `/challenges/$categoryId/$slug`, add a fourth refine, placed last so structural errors report first:

```ts
.refine((challenge) => /^[a-z0-9]+(-[a-z0-9]+)*$/.test(challenge.id.split('/')[1] ?? ''), {
  message: 'the slug after the slash must be kebab-case: lowercase letters, digits, single hyphens',
  path: ['id'],
})
```

The `?? ''` is load-bearing, not stylistic: `test(undefined)` returns `true`, because `undefined` coerces to the string `"undefined"`, which is valid kebab-case. Also add a test for the *existing* "exactly one slash" refine — it shipped with zero coverage, and `'css-transitions/sub/hover-lift'` isolates it, since `'sub'` is legal kebab-case.

**11 · Task 9 Step 3 — the cast in `readChallengeExport` fails lint.** oxlint rejects `(moduleValue as Record<string, unknown>)['challenge']` with `no-unsafe-type-assertion`. Use `in`-operator narrowing: `return 'challenge' in moduleValue ? moduleValue.challenge : undefined;`

**Also in Task 9: `buildRegistry` must not be able to throw, and duplicate ids are not impossible.** Wrap the per-module body — export read through parse — in a `try`/`catch` that records a `RegistryError`; a throwing getter anywhere in the challenge object otherwise aborts every module not yet visited, defeating the accumulate-don't-throw design. And the original comment claiming duplicate ids are "structurally impossible" is **false**: `idFromModulePath` is not injective over arbitrary keys, so `'./a/b.ts'` and `'a/b.ts'` both derive `a/b`, both pass, and `byId` silently collapses with no error. Track a `seenIds` set and reject a repeat.

**12 · Task 9 Step 1 — test 6's fixture cannot detect the sort's removal.** `waapi/bounce-in` + `css-transitions/hover-lift` sort identically by path and by id. Use a three-module fixture including that pair. Put the throwing module **first** in any accumulation test — that is what distinguishes real continue-after-error from a future `break`-instead-of-`continue` regression.

- [ ] **Step 5: Write `scripts/check-no-disable.mjs`**

The scanned roots deliberately exclude `scripts/`, because this file and its test both contain the pattern by necessity.

```js
import { readdirSync, readFileSync, statSync } from 'node:fs';
import { join } from 'node:path';

const DEFAULT_ROOTS = ['src', 'sandbox', 'server'];
const EXTENSIONS = new Set(['.ts', '.tsx', '.css', '.js', '.mjs', '.html']);
const PATTERN = /(?:oxlint|eslint)-disable/;

function walk(dir, files = []) {
  let entries;
  try {
    entries = readdirSync(dir);
  } catch {
    return files;
  }
  for (const entry of entries) {
    const full = join(dir, entry);
    if (statSync(full).isDirectory()) {
      if (entry !== 'node_modules') walk(full, files);
    } else if (EXTENSIONS.has(entry.slice(entry.lastIndexOf('.')))) {
      files.push(full);
    }
  }
  return files;
}

export function findDisableComments(roots = DEFAULT_ROOTS) {
  const hits = [];
  for (const root of roots) {
    for (const file of walk(root)) {
      const lines = readFileSync(file, 'utf8').split('\n');
      lines.forEach((text, index) => {
        if (PATTERN.test(text)) hits.push({ file, line: index + 1, text: text.trim() });
      });
    }
  }
  return hits;
}

if (import.meta.filename === process.argv[1]) {
  const hits = findDisableComments();
  if (hits.length > 0) {
    console.error('Lint disable comments are not permitted in this project:\n');
    for (const hit of hits) console.error(`  ${hit.file}:${hit.line}  ${hit.text}`);
    process.exit(1);
  }
  console.log('No lint disable comments found.');
}
```

import { z } from 'zod';

import { CATEGORY_IDS } from '@/challenges/categories';
import { SERIES_IDS } from '@/challenges/series';
import type { Challenge } from '@/challenges/types';

const filesSchema = z
  .record(z.string().min(1), z.string())
  .refine((files) => Object.keys(files).length > 0, { message: 'must contain at least one file' });

const rubricItemSchema = z.strictObject({
  id: z.string().min(1),
  label: z.string().min(1),
  detail: z.string().min(1).optional(),
});

const baseChallengeSchema = z.strictObject({
  id: z.string().min(1),
  title: z.string().min(1),
  categoryId: z.enum(CATEGORY_IDS),
  difficulty: z.enum(['novice', 'intermediate', 'advanced', 'expert']),
  tech: z.array(z.enum(['css', 'tailwind', 'ts', 'react', 'motion', 'svg', 'waapi'])).min(1),
  runtime: z.enum(['dom', 'react', 'module']),
  brief: z.string().min(1),
  goals: z.array(z.string().min(1)).min(1),
  starter: filesSchema,
  solution: filesSchema,
  explanation: z.string().min(1),
  gradeMode: z.enum(['auto', 'rubric', 'hybrid']),
  rubric: z.array(rubricItemSchema).min(1).optional(),
  hints: z.array(z.string().min(1)),
  series: z.strictObject({ id: z.enum(SERIES_IDS), label: z.string().min(1) }).optional(),
  relatedIds: z.array(z.string().min(1)),
  estimatedMinutes: z.number().int().positive(),
  tags: z.array(z.string().min(1)),
  graderTimeoutMs: z.number().int().positive().optional(),
});

export const challengeSchema = baseChallengeSchema
  .refine((challenge) => challenge.id.startsWith(`${challenge.categoryId}/`), {
    message: 'id must start with the categoryId, as `${categoryId}/${slug}`',
    path: ['id'],
  })
  .refine((challenge) => challenge.id.split('/').length === 2, {
    message: 'id must contain exactly one slash',
    path: ['id'],
  })
  .refine((challenge) => challenge.gradeMode === 'auto' || (challenge.rubric?.length ?? 0) > 0, {
    message: 'a rubric is required when gradeMode is "rubric" or "hybrid"',
    path: ['rubric'],
  });

export type ParseChallengeResult =
  | { success: true; data: Challenge }
  | { success: false; issues: string[] };

export function safeParseChallenge(input: unknown): ParseChallengeResult {
  const result = challengeSchema.safeParse(input);
  if (result.success) {
    // No cast: Zod's mutable output arrays are assignable to Challenge's readonly ones,
    // and `.optional()` produces exactly the `?: T | undefined` shape the interface declares.
    // If this line fails to compile, the schema and the interface have genuinely diverged —
    // fix whichever is wrong rather than casting the mismatch away.
    return { success: true, data: result.data };
  }
  return {
    success: false,
    issues: result.error.issues.map((issue) => `${issue.path.join('.') || '<root>'}: ${issue.message}`),
  };
}

export function parseChallenge(input: unknown): Challenge {
  const result = safeParseChallenge(input);
  if (!result.success) {
    throw new Error(`Invalid challenge:\n  ${result.issues.join('\n  ')}`);
  }
  return result.data;
}

```ts
import { safeParseChallenge } from '@/challenges/schema';
import type { Challenge } from '@/challenges/types';

export interface RegistryError {
  modulePath: string;
  issues: string[];
}

export interface Registry {
  challenges: readonly Challenge[];
  byId: ReadonlyMap<string, Challenge>;
  errors: readonly RegistryError[];
}

/** `./css-transitions/hover-lift.ts` -> `css-transitions/hover-lift` */
function idFromModulePath(modulePath: string): string {
  return modulePath.replace(/^\.\//, '').replace(/\.ts$/, '');
}

function readChallengeExport(moduleValue: unknown): unknown {
  if (typeof moduleValue !== 'object' || moduleValue === null) return undefined;
  return (moduleValue as Record<string, unknown>)['challenge'];
}

export function buildRegistry(modules: Record<string, unknown>): Registry {
  const challenges: Challenge[] = [];
  const errors: RegistryError[] = [];

  for (const modulePath of Object.keys(modules).sort()) {
    const exported = readChallengeExport(modules[modulePath]);

    if (exported === undefined) {
      errors.push({ modulePath, issues: ['module must export a `challenge` constant'] });
      continue;
    }

    const parsed = safeParseChallenge(exported);
    if (!parsed.success) {
      errors.push({ modulePath, issues: parsed.issues });
      continue;
    }

    const expectedId = idFromModulePath(modulePath);
    if (parsed.data.id !== expectedId) {
      errors.push({
        modulePath,
        issues: [`id "${parsed.data.id}" does not match its file path, which implies "${expectedId}"`],
      });
      continue;
    }

    challenges.push(parsed.data);
  }

  challenges.sort((a, b) => a.id.localeCompare(b.id));

  // Ids are derived from module paths, and a module map cannot hold the same path twice,
  // so duplicate ids are structurally impossible here. No duplicate check is needed.
  const byId = new Map<string, Challenge>(challenges.map((entry) => [entry.id, entry]));

  return { challenges, byId, errors };
}

// Grader and test modules live beside challenge modules and must not be collected.
const challengeModules: Record<string, unknown> = import.meta.glob(
  ['./*/*.ts', '!./*/*.grade.ts', '!./*/*.test.ts'],
  { eager: true },
);

export const challengeRegistry: Registry = buildRegistry(challengeModules);

export function getChallenge(id: string): Challenge | undefined {
  return challengeRegistry.byId.get(id);
}
```

export const challenge: Challenge = {
  id: 'css-transitions/hover-lift',
  title: 'Hover lift',
  categoryId: 'css-transitions',
  difficulty: 'novice',
  tech: ['css'],
  runtime: 'dom',
  estimatedMinutes: 6,
  tags: ['transition', 'transform', 'compositor'],
  brief: [
    'The card below jumps to its hovered state with no animation.',
    '',
    'Make it rise smoothly on hover: a 200ms lift of 6px with a deeper shadow.',
    'Animate only properties the compositor can handle on its own.',
  ].join('\n'),
  goals: [
    'Hovering the card moves it up by 6px over roughly 200ms.',
    'The shadow deepens over the same period.',
    'Only transform and opacity-backed properties are transitioned — no `all`, no `top`, no `margin`.',
  ],
  starter: {
    'index.html': '<div class="card">Hover me</div>\n',
    'styles.css': [
      '.card {',
      '  display: grid;',
      '  place-items: center;',
      '  width: 220px;',
      '  height: 120px;',
      '  border-radius: 12px;',
      '  background: white;',
      '  box-shadow: 0 1px 2px rgb(0 0 0 / 0.08);',
      '}',
      '',
      '.card:hover {',
      '  /* Make this animate. */',
      '}',
      '',
    ].join('\n'),
  },
  solution: {
    'index.html': '<div class="card">Hover me</div>\n',
    'styles.css': [
      '.card {',
      '  display: grid;',
      '  place-items: center;',
      '  width: 220px;',
      '  height: 120px;',
      '  border-radius: 12px;',
      '  background: white;',
      '  box-shadow: 0 1px 2px rgb(0 0 0 / 0.08);',
      '  transition:',
      '    transform 200ms cubic-bezier(0.2, 0, 0, 1),',
      '    box-shadow 200ms cubic-bezier(0.2, 0, 0, 1);',
      '}',
      '',
      '.card:hover {',
      '  transform: translateY(-6px);',
      '  box-shadow: 0 12px 24px rgb(0 0 0 / 0.16);',
      '}',
      '',
    ].join('\n'),
  },
  explanation: [
    '### Why this works',
    '',
    '`transform` is one of the two properties (with `opacity`) a browser can animate entirely on the',
    'compositor thread. Moving the card with `translateY` never triggers layout or paint, so the',
    'animation survives a busy main thread.',
    '',
    '### Why not `top` or `margin-top`',
    '',
    'Both change geometry, so every frame costs a layout pass for the card and potentially its siblings.',
    'The result looks identical when the page is idle and janks the moment it is not.',
    '',
    '### Why not `transition: all`',
    '',
    '`all` transitions every animatable property that happens to change, including ones you never intended',
    'and ones added later. It is a standing invitation to accidental animation, and it costs style',
    'recalculation on properties you do not care about. Name the properties.',
    '',
    '### The shadow caveat',
    '',
    '`box-shadow` is *not* compositor-friendly — it repaints each frame. At this size it is fine, but',
    'the cheaper pattern for large or frequently animated shadows is a pseudo-element holding the deeper',
    'shadow, with only its `opacity` transitioned. That technique gets its own challenge in the',
    'performance category.',
  ].join('\n'),
  gradeMode: 'auto',
  hints: [
    'The `transition` property belongs on the resting state, not only on `:hover` — otherwise the return trip is instant.',
    'Which two properties can a browser animate without touching layout or paint?',
    'List the transitioned properties explicitly, separated by commas.',
  ],
  relatedIds: [],
};
